The four gates

A document is processed without a person only if it passes all four.

  1. No validation errors. Something that does not add up is never paid automatically, however clearly it was printed.
  2. Confidence at or above the gate. How well the document was read – built from the type score, each required field's own score, scanner repairs and warnings. Never from asking a model how sure it is.
  3. Every required field clears its own bar. Checked one by one, because an average lets a crisp supplier name hide an unreadable total.
  4. The amount is below the limit. Not a doubt about the reading. A policy: the cost of being wrong scales with the number, and the cost of a human glance does not.

Why errors do not lower confidence

A crisp PDF whose line items do not add up was read perfectly and is wrong. A smudged fax that adds up may have been misread and is at least self-consistent. Those two need different things from a person, so the pipeline keeps “did I read it correctly?” and “is it correct?” as separate answers.

Where the model is used

Three places, all optional: transcribing a scan that has no text layer, naming a document the keyword rules could not place, and filling a required field the label patterns missed. Everything else – labels, sums, checksums, dates, duplicates, confidence, the decision – is ordinary code. On the sample folder that works out to one model call across thirteen documents.
