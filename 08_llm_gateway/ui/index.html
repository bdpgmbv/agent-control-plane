Is the new prompt actually better?

Two prompts, the same questions, and an honest answer about whether the difference means anything. Send a few dozen requests and the platform will tell you it cannot tell yet – which is the point. Keep going and it will name a winner, with the interval it is confident about.

An A/B result without an interval is a coin flip with extra steps

Variant A got 62% right and variant B got 71%. With twenty requests each, “B had an easier sample” is overwhelmingly the more likely explanation – and a platform that prints B wins has told you nothing while sounding like it told you something.

So this one reports an interval rather than a verdict, and refuses to name a winner until the interval excludes zero. When it cannot tell, it says how many more samples would settle it. “Not yet” is a result.

Retrying and falling back are different questions

Retrying asks “was that just bad luck?”. Falling back asks “is this provider usable at all?”. A rate limit is worth both. A malformed request is worth neither – it will be just as malformed at the next provider, and trying anyway turns one clear error into three slow ones.

The scope is part of the cache key

Project 01 in this series shipped a semantic cache that served one user's answer to another, because the similarity search found the nearest entry first and the permission check came second. A check that comes after the match is one somebody will eventually move. Here the scope is in the key and in the candidate query, so there is no code path that can find an entry from another scope at all.

Why percentiles, not averages

A mean latency of two seconds could be everything taking two seconds, or 95% taking half a second and one request in twenty taking thirty. Only one of those is a problem and the mean cannot tell you which you have.
